# Market Snapshot Copier

Приложение на Python, которое собирает публичные рыночные данные по ETHUSDT
(или любой другой паре) с биржи **BingX**, считает технические индикаторы,
формирует текстовый отчёт и по умолчанию сразу отправляет его **до 3
AI-моделям параллельно** (например, через шлюз
[APINET.CLOUD](https://apinet.cloud/), OpenAI-совместимый endpoint), чтобы
сравнить их сигналы side by side. Есть два стиля анализа (скальпинг / свинг),
живой локальный дашборд с кнопками обновления по каждой модели отдельно и
трекер точности, который со временем показывает, какая модель реально чаще
угадывает направление, а не просто звучит увереннее.

Флагом `--no-ai` можно отключить отправку в AI и просто скопировать отчёт
вручную (например, в ChatGPT) — исходный сценарий приложения.

## Возможности

- **Сбор рыночных данных с BingX** (публичные эндпоинты, без API-ключа):
  текущая цена, свечи 1m/5m/15m/1h с индикаторами (EMA20/50/200, RSI14, MACD,
  ATR14, Bollinger Bands), стакан заявок, funding rate (текущий + история
  settlement'ов), open interest (+ локальный тренд), уровни
  поддержки/сопротивления.
- **Сравнение до 3 AI-моделей параллельно** — каждая на своём ключе/провайдере
  через OpenAI-совместимый `chat/completions`. Модель без ключа просто
  пропускается.
- **Два стиля анализа** — scalping (узкие 1m/5m-стопы, минуты) и swing (стопы
  за структурой 15m/1h, часы-сутки) — считаются одновременно, переключаются в
  дашборде без повторного запроса.
- **Строгий JSON-протокол ответов** — каждая модель обязана вернуть один
  JSON-объект по фиксированной схеме (сигнал, статус входа, зона входа, стоп,
  TP1-3, причины, риски, условия отмены), без свободного текста и без
  regex-разбора чисел. Невалидный JSON — один запрос на исправление, дальше
  честный статус `INVALID_RESPONSE`.
- **Программный валидатор торгового плана** (`trade_validator.py`) —
  перепроверяет каждый распарсенный план кодом (порядок stop/TP, дистанция от
  цены и от стопа в ATR, Risk/Reward не хуже минимума для режима и т.д.).
  План, не прошедший проверку, никогда не показывается как готовый сигнал.
- **Консенсус моделей, посчитанный кодом** (`consensus_engine.py`, не AI) —
  над карточками моделей одна карточка «Итоговый вывод»: общий сигнал,
  сила консенсуса (сильный/умеренный/слабый/конфликт/мало данных), сколько
  моделей реально согласны, средняя уверенность.
- **Карточка торгового сценария** — синтезированный (медианный) план по
  моделям, согласным с консенсусом: зона входа, stop loss, TP1-3, R:R,
  когда сформирован и сколько ещё действителен. Для WAIT — отдельный блок
  с условиями, при которых сценарий появится.
- **HTML-дашборд**, компактные карточки моделей (сигнал LONG/SHORT/WAIT,
  статус входа, уверенность модели, вход, стоп, TP1, статус валидатора,
  бейдж свежести сигнала) — причины/риски/условия отмены/полный JSON-ответ
  скрыты по умолчанию за отдельными раскрывашками, а не одной стеной текста.
- **Срок действия сигнала** — каждый план "истекает" (`valid_for_minutes`
  из ответа модели); просроченная карточка визуально гаснет, помечается
  «Сигнал устарел» и не участвует в консенсусе, пока её не обновят.
- **Живой локальный сервер** (`--serve` / `server.py`) — кнопка «Обновить»
  реально дёргает BingX/AI, причём можно обновить **всю активную вкладку**
  или **только одну карточку** (одну модель), не трогая остальные.
- **Трекер точности прогнозов** — каждый реальный ответ модели логируется
  локально, а через горизонт (30 мин скальпинг / 8 ч свинг) сравнивается
  направление прогноза с фактическим движением цены. На дашборде — компактная
  панель с win-rate по каждой модели.

## Что приложение НЕ делает

- Не торгует и не открывает/закрывает сделки — ни на BingX, ни где-либо ещё.
- Не подписывает и не отправляет никаких приватных/торговых запросов на BingX (используются только публичные `quote`-эндпоинты, API-ключ не нужен).
- Не подключается к вашему торговому аккаунту — позицию вы указываете вручную в `.env`.
- Отправляет собранные рыночные данные в AI API **только для моделей, у которых вы сами указали ключ** (`AI_API_KEY` / `AI2_API_KEY`) в `.env`, и только если не передан `--no-ai`. Без ключей — или с флагом `--no-ai` — приложение работает в старом режиме: только собирает и выводит/сохраняет текстовый отчёт, никуда его не отправляя.
- Необязательный live-сервер (`--serve` / `server.py`) слушает только `127.0.0.1` — недоступен с других устройств/из интернета, пока вы сами не пробросите порт наружу (чего мы не рекомендуем без авторизации).

## Установка

### 1. Клонируйте/скопируйте проект

```bash
cd market_snapshot_copier
```

### 2. Создайте виртуальное окружение

Windows (PowerShell):

```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

macOS / Linux:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

### 4. Настройте `.env`

Скопируйте пример и при желании отредактируйте:

```bash
cp .env.example .env
```

Содержимое `.env`:

```
SYMBOL=ETHUSDT
TRADING_MODE=scalping

POSITION=NONE
ENTRY_PRICE=
LEVERAGE=
STOP_LOSS=
TAKE_PROFIT=

KLINE_LIMIT=220
ORDERBOOK_DEPTH=20
ORDERBOOK_DISPLAY_DEPTH=8
REQUEST_TIMEOUT=10
FUNDING_HISTORY_LIMIT=5

AI_API_KEY=
AI_BASE_URL=https://apinet.cloud/v1
AI_MODEL=gpt-5.1-all
AI_LABEL=NeuroTrade-gpt

AI2_API_KEY=
AI2_BASE_URL=https://apinet.cloud/v1
AI2_MODEL=claude-opus-5
AI2_LABEL=NeuroTrade-claude

AI_REQUEST_TIMEOUT=180

DASHBOARD_HOST=127.0.0.1
DASHBOARD_PORT=47913
```

- `TRADING_MODE` — `scalping` (по умолчанию) или `swing`:
  - **scalping** — узкие стопы/входы по 1m/5m, расчёт на удержание позиции
    минуты.
  - **swing** — стоп размещается за структурными уровнями 15m/1h (EMA20/50,
    локальные экстремумы), цели берутся на более удалённых
    уровнях поддержки/сопротивления так, чтобы риск/прибыль был не хуже
    1:1.5, расчёт на удержание от нескольких часов до суток. Меняется и
    текст задачи в самом отчёте, и системный промпт для всех AI-моделей —
    сравнение в дашборде остаётся честным (все модели анализируют в одном
    стиле). Можно переопределить на конкретный запуск флагом `--mode swing`
    без правки `.env`.
- `POSITION` — `NONE`, `LONG` или `SHORT`. Если у вас открыта позиция, укажите
  её параметры (`ENTRY_PRICE`, `LEVERAGE`, `STOP_LOSS`, `TAKE_PROFIT`), и они
  попадут в отчёт. Данные вводятся вручную — приложение не подключается к
  вашему торговому аккаунту.
- `ORDERBOOK_DEPTH` — сколько уровней стакана реально запрашивается у BingX
  (используется для расчёта дисбаланса bid/ask); `ORDERBOOK_DISPLAY_DEPTH` —
  сколько из них построчно печатается в отчёте (остальное участвует только в
  агрегированном дисбалансе, чтобы не раздувать промпт).
- `FUNDING_HISTORY_LIMIT` — сколько последних settlement'ов funding rate
  (BingX платит их примерно каждые 8 часов) показывать в отчёте, чтобы AI
  видел тренд, а не разовое значение.
- `AI_API_KEY` / `AI2_API_KEY` — ключи до двух независимых
  моделей. Модель без ключа просто пропускается (не ошибка) — можно оставить
  только одну заполненной. Если не заполнена ни одна — приложение завершится
  с понятной ошибкой и предложит либо задать хотя бы один ключ, либо
  запускать с `--no-ai`.
- `AI_BASE_URL` / `AI2_BASE_URL` — базовый URL
  OpenAI-совместимого `chat/completions` эндпоинта для каждой модели. По
  умолчанию обе указывают на шлюз APINET.CLOUD, но у каждой модели может
  быть свой провайдер/URL.
- `AI_MODEL` / `AI2_MODEL` — имя модели у соответствующего
  провайдера.
- `AI_LABEL` / `AI2_LABEL` — человекочитаемое имя модели для
  вывода в терминале и в дашборде (по умолчанию — «NeuroTrade-gpt»,
  «NeuroTrade-claude»).
- `DASHBOARD_HOST` / `DASHBOARD_PORT` — где слушает живой сервер дашборда
  (см. раздел «Живой дашборд» ниже).

Есть и другие необязательные переменные с разумными дефолтами в коде —
`OI_HISTORY_MAX_ENTRIES`, `PREDICTION_HISTORY_MAX_ENTRIES`,
`PREDICTION_HORIZON_SCALPING_SECONDS`, `PREDICTION_HORIZON_SWING_SECONDS` —
их не нужно трогать, если не хотите потюнить трекер точности (см. ниже).

> ⚠️ Если вы пользуетесь агрегатором вроде APINET.CLOUD — не доверяйте
> названию модели вслепую. Мы на практике столкнулись с тем, что модель,
> подписанная в каталоге как «Claude», на самом деле была другим,
> немаркированным движком (представлялась как «Kiro» и явно отказывалась
> называть себя Claude). Перед тем как полагаться на модель, проверьте её
> ответ на простой контрольный вопрос и сверьте с `/v1/models` /
> `/api/pricing` вашего шлюза, есть ли у неё официальное описание и
> совпадает ли поведение с ожидаемым. Также имейте в виду, что у таких
> шлюзов «баланс кошелька» и «квота API» могут быть разными сущностями —
> ошибка вида `insufficient_user_quota` при формально пополненном балансе
> означает, что нужно искать отдельный раздел квоты/лимитов на сайте шлюза.

## Запуск

```bash
python main.py
```

По умолчанию это: соберёт данные с BingX → построит текстовый отчёт →
параллельно отправит его во все настроенные AI-модели → выведет и сохранит
их ответы текстом и в виде HTML-дашборда.

Дополнительные флаги:

```bash
python main.py --symbol ETHUSDT             # другая пара (по умолчанию ETHUSDT)
python main.py --mode swing                 # какая вкладка активна по умолчанию в дашборде
python main.py --output my_report.txt       # другой путь для файла с рыночными данными
python main.py --no-save                    # не сохранять текстовый отчёт в файл
python main.py --no-ai                      # не отправлять данные в AI, только собрать отчёт
python main.py --ai-output my_answer.txt    # другой путь для текстового файла с ответами AI
python main.py --dashboard-output my.html   # другой путь для HTML-дашборда
python main.py --no-dashboard               # не строить HTML-дашборд (только текст)
python main.py --serve                      # плюс живой сервер дашборда — см. раздел ниже
```

После запуска:
1. Текстовый отчёт с рыночными данными выводится в терминал и сохраняется в
   `market_snapshot.txt` (если не передан `--no-save`) — это происходит
   всегда, независимо от режима AI.
2. Если не передан `--no-ai`, отчёт параллельно отправляется во все
   настроенные модели (у кого задан ключ) **сразу для обоих стилей —
   scalping и swing** (6 запросов вместо 3, но все летят одним параллельным
   пулом). Ответ каждой модели выводится в терминал под своим заголовком и
   сохраняется в `ai_analysis.txt` (или путь из `--ai-output`) — по одному
   разделу на модель и стиль, включая текст ошибки, если конкретная модель
   не ответила.
3. Если не передан `--no-dashboard`, дополнительно собирается наглядный
   `dashboard.html` (или путь из `--dashboard-output`) — переключатель
   «скальпинг / свинг» наверху, карточка на каждую модель с автоматически
   определённым сигналом (LONG/SHORT/WAIT), сводкой (вероятность/вход/стоп/
   TP1), временем последнего обновления именно этой карточки и полным
   текстом анализа, плюс панель точности прогнозов внизу страницы. `--mode`
   определяет, какая вкладка открыта по умолчанию. Открывается просто
   двойным кликом в браузере, ничего никуда не отправляет — если не запущен
   `--serve` (см. ниже).

Если хотя бы одна модель ответила успешно — код возврата 0. Если сбой у
одной-двух моделей, остальные всё равно попадают в отчёт и дашборд — это не
считается фатальной ошибкой.

Если хотите пользоваться приложением как раньше — только текстовый отчёт для
ручной вставки в ChatGPT, без автоматической отправки — запускайте с
`--no-ai` (можно и не задавать ни один `AI*_API_KEY`).

## Живой дашборд (сервер)

По умолчанию `dashboard.html` — статический файл: кнопка «Обновить» ничего
не может получить сама, пока вы не перезапустите `python main.py` вручную.
Чтобы кнопки реально дёргали BingX/AI и показывали свежие данные, запустите
локальный сервер:

```bash
python main.py --serve      # сначала обычный прогон, потом сервер на его данных
# или отдельно, без предварительного python main.py:
python server.py
```

Сервер поднимается на `http://127.0.0.1:47913/` (порт — `DASHBOARD_PORT` в
`.env`) и открывает эту страницу в браузере автоматически.

**Обновление — по вкладке или по одной модели:**

- Кнопка «Обновить» в шапке страницы обновляет **все модели активной сейчас
  вкладки** (скальпинг ИЛИ свинг) — вторая вкладка не трогается.
- У каждой карточки модели есть своя маленькая кнопка ↻ — обновляет **только
  эту одну модель**, не трогая ни другие карточки, ни вторую вкладку. Удобно,
  когда нужно перепроверить/протестировать одну модель, не пересчитывая (и не
  оплачивая) все три сразу.
- В обоих случаях сервер заново запрашивает у BingX свежие данные (это
  бесплатно — публичные эндпоинты) и AI только для того, что реально
  обновляется, сохраняет обновлённый `dashboard.html` на диск и перезагружает
  страницу.
- На каждую пару «режим + модель» (а не просто на режим) действует
  30-секундный кулдаун — повторный клик по той же карточке/кнопке раньше
  этого времени вернёт понятное сообщение вместо повторного платного запроса.
- Если сервер не запущен (файл открыт напрямую) или недоступен — кнопка
  покажет понятное сообщение под собой, а не сломается молча.
- Есть отдельный `GET /api/status` — безопасный, ничего не запрашивает и не
  тратит, просто отдаёт текущее состояние (что обновляется прямо сейчас,
  сколько моделей ответили успешно, когда был последний апдейт). Используйте
  его, если нужно проверить «жив ли сервер» — не дёргайте `/api/refresh`
  ради проверки, у него есть побочный эффект (реальный платный AI-запрос).

**Перезапуск без новых трат:** сервер сохраняет своё состояние в
`dashboard_cache.pkl` при каждом обновлении. Если процесс перезапустить
(например, после обновления кода), он сначала попробует восстановить
последнее состояние из этого кеша и только если кеша нет — пойдёт за новыми
данными в BingX/AI. То есть обычный `Ctrl+C` → `python server.py` никогда
сам по себе не тратит AI-квоту.

**Про безопасность:** сервер слушает только `127.0.0.1` (только эта
машина) — это осознанный выбор, не просто настройка по умолчанию. Он умеет
инициировать настоящие (платные) запросы к вашим AI API и показывает вашу
позицию — не меняйте `DASHBOARD_HOST` на `0.0.0.0` и не пробрасывайте порт
наружу (port forwarding/ngrok и т.п.), если не добавите перед ним
авторизацию сами. Номер порта (`47913`) выбран просто необычным, чтобы не
конфликтовать с другими локальными дев-серверами — это не защита сама по
себе, защищает именно привязка к `127.0.0.1`.

Остановить сервер — `Ctrl+C` в терминале, где он запущен.

## Более точные рыночные данные

Помимо точечных значений, отчёт для AI теперь включает динамику:

- **Стакан заявок** — реально запрашивается более глубокий срез
  (`ORDERBOOK_DEPTH`, по умолчанию 20 уровней), построчно в отчёт попадает
  только верхняя часть (`ORDERBOOK_DISPLAY_DEPTH`, по умолчанию 8), а по всей
  запрошенной глубине считается и печатается **дисбаланс объёма bid/ask** —
  например, «56.4% объёма на стороне покупателей».
- **Funding rate** — помимо текущего/предсказанного значения, отчёт содержит
  историю последних settlement'ов (BingX платит их примерно раз в 8 часов),
  чтобы AI видел, растёт ставка или падает, а не разовую цифру.
- **Open interest** — у BingX нет публичного эндпоинта истории OI, поэтому
  приложение сохраняет собственный локальный ряд (`oi_history.jsonl`,
  создаётся автоматически) и на каждом новом снимке сравнивает текущее
  значение с предыдущим сохранённым — в отчёте появляется реальное изменение
  OI и то, сколько времени прошло с прошлого снимка. При самом первом запуске
  будет «н/д» (сравнивать не с чем) — со второго обновления тренд уже виден.

## Точность прогнозов моделей

Каждый успешный (validator-approved) ответ модели логируется локально в
`predictions.jsonl`: режим, модель, сигнал, зона входа, stop loss, take
profits, время. При каждом новом сборе данных приложение проверяет прогнозы,
у которых истёк горизонт оценки (по умолчанию **30 минут для скальпинга и
8 часов для свинга**, настраивается через `PREDICTION_HORIZON_SCALPING_SECONDS`
/ `PREDICTION_HORIZON_SWING_SECONDS`).

**Оценка — по реальному пути цены, не по цене на дедлайн.** Для каждого
просроченного прогноза приложение загружает у BingX исторические 1-минутные
свечи именно за окно `[время прогноза, время прогноза + горизонт]`
(бесплатный публичный эндпоинт с `startTime`/`endTime`) и проходит по ним
(`outcome_simulator.py`): что случилось раньше — стоп, TP1, TP2, TP3, или
ни то ни другое (`TIMEOUT`). Если в одной свече задеты и стоп, и цель
одновременно — внутрисвечной порядок по OHLC не восстановить, это
помечается `AMBIGUOUS` и **консервативно** считается как стоп. Результат
переводится в **R** (единицы риска = |вход − стоп|) с вычетом комиссии и
проскальзывания (`TRADING_COMMISSION_PCT`/`TRADING_SLIPPAGE_PCT` в `.env`,
по умолчанию 0.05%/0.02%). Дополнительно считаются MFE/MAE (максимальное
благоприятное/неблагоприятное отклонение цены за весь путь, тоже в R).

Упрощения (сознательные, не баг): вход считается мгновенным по середине
зоны входа в момент прогноза, а не ожиданием отката/пробоя; свечи — всегда
1-минутные независимо от режима. Сигналы WAIT не оцениваются направленно
(это не ставка на сторону), но по-прежнему считаются отдельно.

На дашборде — панель «Точность прогнозов» **отдельно на скальпинг и на
свинг** (переключается вместе с остальным дашбордом, цифры этих двух
режимов никогда не смешиваются): по одной строке на модель с
цветной полосой-метром (зелёная ≥60% доли прогнозов с R>0, жёлтая 40-59%,
красная <40%, серая — оценённых прогнозов меньше `MIN_SAMPLE_FOR_STATS`
(по умолчанию 3) и цифре рано доверять — рядом всегда честно написан размер
выборки, например «2 победы из 3», никогда голый процент). Под полосой —
expectancy (средний R), profit factor (сумма выигрышей / сумма проигрышей;
`∞`, если проигрышей ещё не было), медиана R, максимальная просадка по
последовательности сделок, и разбивка по причине выхода (TP1/TP2/TP3/SL/
TIMEOUT/AMBIGUOUS).

**Миграция**: прогнозы, записанные до этого обновления (старый формат —
просто win/loss/flat без R), не пересчитываются задним числом — для этого
нужно заново запросить у BingX уже частично истёкшее окно, а по объёму это
была synthetic-тестовая история, а не что-то ценное. Они просто не попадают
в новую R-статистику; счётчик «всего прогнозов» их видит, но «оценено»
показывает 0, пока не накопятся новые.

## Строгий JSON-формат ответов и валидация

Раньше сигнал/вход/стоп/TP1/вероятность вытаскивались регулярками из
свободного текста ответа — хрупко и не всегда точно. Теперь каждая модель
обязана ответить одним JSON-объектом по схеме `ai_schema.TradePlan`
(Pydantic): `signal` (LONG/SHORT/WAIT), `entry_status` (ENTER_NOW /
WAIT_PULLBACK / WAIT_BREAKOUT / WAIT_CONFIRMATION / LATE_ENTRY / REJECTED /
NO_TRADE), `confidence` (0-100), `market_regime`, зона входа, `stop_loss`,
список `take_profits`, `risk_reward`, сроки действия, причины/риски/условия
отмены. Системный промпт явно описывает схему и требует «только JSON, без
markdown и пояснений».

Если ответ не парсится или не проходит Pydantic-валидацию:
1. Сырой ответ и причина сохраняются в локальный лог `neurotrade.log`.
2. Модели отправляется один повторный запрос: «твой предыдущий ответ не
   прошёл проверку схемы: ..., верни исправленный JSON».
3. Если и вторая попытка невалидна — карточка помечается как «ОШИБКА»
   (`error_code=INVALID_JSON`), полноценным сигналом не считается.

Успешно распарсенный план дополнительно проверяется кодом в
`trade_validator.py` — без обращения к AI: правильная сторона stop
loss/TP относительно входа, порядок TP1 < TP2 < TP3 (или наоборот для
SHORT), вход не дальше 3 ATR от текущей цены, стоп не уже 0.15 ATR и не шире
6 ATR, стоп не внутри текущего спреда, пересчитанный Risk/Reward не хуже
минимума для режима (scalping ≥1.0, swing ≥1.5), а для WAIT — обязательны
`wait_conditions`/`invalidation_conditions`. План, отклонённый валидатором,
показывается на дашборде с пометкой «Отклонено валидатором» и списком
конкретных причин — никогда как обычный зелёный сигнал.

«Вероятность» переименована в **«Уверенность модели»** — рядом есть
пояснение (при наведении/фокусе): это субъективная оценка самой модели, а не
статистически подтверждённая вероятность успеха.

**Пользователю, ошибки видны только в нормализованном виде** —
`AI_AUTH_ERROR`, `RATE_LIMIT`, `PROVIDER_TIMEOUT`, `INVALID_JSON`,
`VALIDATION_FAILED`, `NETWORK_ERROR`, `BINGX_UNAVAILABLE`, `UNKNOWN_ERROR`.
Сырые URL шлюза, тела ответов провайдера и другие технические детали в
интерфейс не попадают — только в `neurotrade.log` (в `.gitignore`, на диск не
коммитится).

**Миграция кеша**: если у вас уже был `dashboard_cache.pkl` от версии до этого
обновления, карточки в нём после перезапуска сервера покажут «Старый формат»
вместо сигнала — это не ошибка, а честное указание, что для этой карточки
ещё нет структурированного плана. Нажмите ↻ на карточке (или на всей
вкладке), чтобы она заново посчиталась в новом формате.

## Консенсус моделей и карточка сценария

Над карточками моделей — «Итоговый вывод» (`consensus_engine.py`),
посчитанный кодом из уже провалидированных JSON-планов, без отдельного
обращения к AI:

- Голос модели засчитывается, только если её план прошёл валидатор
  (`result.ok`) **и** сигнал ещё не истёк (`signal_freshness.py`, см. ниже).
- Правила: все голоса совпадают → **сильный** консенсус (≥3 голосов) или
  **умеренный** (2); LONG и SHORT присутствуют одновременно среди голосов →
  **конфликт**, итог WAIT; одно направление в большинстве, остальные WAIT →
  умеренный/слабый; 0-1 валидный голос → **«недостаточно данных»**.
- Взвешивание по исторической точности модели/режиму рынка/паре **пока не
  делается** — текущая статистика в `predictions.jsonl` не разбита по
  режиму (скальпинг/свинг смешаны), а взвешивать консенсус по некорректно
  смешанной цифре хуже, чем не взвешивать вообще. Сейчас — равный вес
  голоса + средняя `confidence` среди согласных моделей.

Под «Итоговым выводом» — «Карточка сценария»: для LONG/SHORT это
**медианные** зона входа/stop loss/TP1-3 среди согласных моделей (не
уровни одной произвольной модели), пересчитанный R:R, когда сформирован и
сколько ещё действителен. Для WAIT — отдельный блок: почему сейчас нет
преимущества для входа и какие условия названы моделями (единым списком —
разбивка на «условия для LONG» / «условия для SHORT» потребовала бы менять
схему ответа и не сделана в этой версии).

**Срок действия сигнала**: каждый план несёт `valid_for_minutes` — сколько
минут модель считает его актуальным. Дашборд показывает возраст
(«12 мин назад») и остаток («осталось 14 мин») для каждой карточки и для
синтезированного плана. Как только время истекло — карточка гаснет
(`opacity`), помечается «Сигнал устарел» и перестаёт участвовать в
консенсусе, пока вы не обновите её (↻ у карточки или у всей вкладки). Для
скальпинга срок обычно короче, чем для свинга — это задаёт сама модель по
инструкции в промпте, не хардкод в коде.

Верхняя плашка рынка тоже показывает человекочитаемый возраст данных
(«данные обновлены 14 секунд назад») и цветную точку свежести — зелёная
(<2 мин), жёлтая (2-10 мин), красная (>10 мин).

## Обработка ошибок

Приложение отдельно обрабатывает и выводит понятные сообщения (без падения с
трейсбеком, с ненулевым кодом возврата) для:

BingX:
- недоступности API (5xx / сетевые ошибки);
- отсутствия данных в ответе биржи;
- неверного символа (например, опечатка в паре);
- превышения лимита запросов (HTTP 429 / код ошибки лимита);
- проблем с интернет-соединением (обрыв, таймаут, DNS).

AI API (на уровне каждой отдельной модели, не всего запуска), с нормализацией
в короткий код + безопасный текст (см. «Строгий JSON-формат ответов» выше —
сырые детали уходят только в `neurotrade.log`, не в интерфейс):
- отсутствия ключа у конкретной модели — она просто пропускается;
- отсутствия **ни одного** ключа сразу у всех трёх — это уже фатальная
  ошибка (подсказка задать хотя бы один ключ или использовать `--no-ai`);
- ошибки авторизации/квоты (HTTP 401/403 → `AI_AUTH_ERROR`);
- превышения лимита запросов (HTTP 429 → `RATE_LIMIT`);
- тайм-аута (`PROVIDER_TIMEOUT`) и сетевых проблем (`NETWORK_ERROR`);
- невалидного JSON после повторной попытки (`INVALID_JSON`);
- плана, не прошедшего программную валидацию (`VALIDATION_FAILED`).

Если у одной модели произошла ошибка, это не прерывает работу остальных —
её карточка в дашборде и раздел в текстовом файле просто помечаются как
ошибка, а успешные модели показываются как обычно.

Обратите внимание: сбор и сохранение рыночного отчёта (`market_snapshot.txt`)
происходит **до** обращения к AI API, поэтому даже если вся AI-часть упадёт с
ошибкой, собранные данные не теряются — вы просто получите отчёт без анализа
и сможете разобраться с настройкой AI API отдельно.

Покрывают: разбор JSON-ответа модели (валидный, в markdown-ограждении,

## Дисклеймер

Этот инструмент **не является финансовой рекомендацией**. Он собирает и
форматирует публичные рыночные данные, а также (если вы это настроили)
пересылает их в указанные вами AI API (одну или несколько моделей), чтобы
получить текстовый анализ и сравнить их сигналы. Разные модели могут давать
разные и даже противоположные сигналы по одним и тем же данным — дашборд
показывает их все, а не «правильный» ответ. Панель точности прогнозов —
статистика по истории, а не гарантия на будущее. Все торговые решения вы
принимаете самостоятельно и на свой риск — приложение не торгует и не имеет
доступа к вашему торговому аккаунту.
